## 四、演示数据规范

### 设计原则

- store 初始化时**仅在 localStorage 无数据时**填入，之后用户删光也不会自己回来
- 任务数据要覆盖多种组合，保证筛选、排序、统计都有可见效果
- 日期用「相对今天」的偏移生成，不要写死绝对日期，否则过几天全部变成逾期

### 6 条任务

| # | 标题 | 课程 | 知识点 | 截止日期 | 优先级 | 状态 |

| 2 | 整理 Python 异常笔记 | Python | 异常处理 | 今天 −4 天 | 高 | 未完成（逾期） |
| 3 | 完成离散数学复盘 | 离散数学 | 图论 | 今天 −3 天 | 低 | 已完成 |

- 图片加载失败时不影响标题和操作按钮（`alt` 已能兜底，不要用 JS 隐藏整个区域）

## 七、第 2 步：TaskCard + 完成/删除

**目标**：任务卡片成型，能改状态、能删。

### 2.1 `src/components/TaskCard.vue`

| 项目 | 内容 |
| --- | --- |
| props | `task`（必填） |
| emits | `toggle`、`edit`、`delete`、`postpone`、`link-note`、`focus` |
| 展示 | 标题、课程、截止日期、优先级、状态标签 |
| 桌面操作 | 完成/恢复、编辑、延期、关联笔记、删除 全部平铺 |
| 手机操作 | 只显示「完成」+「更多」，更多里展开其余操作 |

用现有全局样式：`.card`、`.tag`、`.btn btn--sm`、`.btn--ghost`，**不要新写按钮样式**。

### 2.2 完成 / 恢复

- 点击后调用 `toggleComplete`，**原地更新**，不弹窗
- 已完成任务即使日期已过，也**不能显示「已逾期」**

### 2.3 删除

- 用 `BaseModal` 做二次确认，标题写明任务名，例如「删除任务「复习二叉树遍历」？」
- 确认按钮用 `.btn--danger`，文案「删除」
- 取消不改任何数据

- [x] 点「恢复未完成」→ 变回未完成；若日期已过则显示「已逾期」
